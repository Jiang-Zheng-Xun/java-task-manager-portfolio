# ADR 0001: Adopt the initial technology baseline

- Status: Accepted
- Date: 2026-09-18

## Context

The project needs a stable and reproducible backend baseline suitable for demonstrating Java and Spring development, relational database integration, automated testing, and continuous integration.

During repository initialization, Spring Initializr did not offer Spring Boot 3.5.16 through its current metadata and rejected the requested version with HTTP 400. Maven artifact resolution and the official Spring Boot documentation confirmed that Spring Boot 3.5.16 remained available and compatible with the selected Java and Maven versions.

## Decision

Use the following technology baseline:

- Java 21
- Spring Boot 3.5.16
- Maven
- PostgreSQL 17
- Flyway
- Docker Compose
- GitHub Actions

Create the initial Maven project skeleton manually instead of changing the approved Spring Boot version solely to match the versions currently exposed by Spring Initializr.

Use PostgreSQL through a Docker Compose service for local development. Install only the PostgreSQL client on the WSL host.

## Rationale

- Java 21 is a long-term support release and matches the project’s development target.
- Spring Boot 3.5.16 provides the approved Spring Boot 3 baseline.
- Maven provides a reproducible build lifecycle for local development and CI.
- PostgreSQL provides a production-relevant relational database.
- Flyway makes schema changes explicit and repeatable.
- Docker Compose keeps the local database isolated and reproducible.
- GitHub Actions provides automated verification for pull requests and protected branches.

## Consequences

### Positive

- Local development and CI use the same Java and PostgreSQL major versions.
- Database schema changes are version-controlled.
- The project can be reproduced from repository instructions.
- Technology choices and their rationale are reviewable.

### Trade-offs

- The Maven skeleton must be maintained manually because the selected Spring Boot version was not generated by Spring Initializr at initialization time.
- Developers must provide a local ignored `.env` file before starting the application.
- Version upgrades require a separate reviewed decision and verification.

## Validation

The baseline is accepted only when:

- `mvn clean verify` succeeds with Java 21.
- The Spring application context test passes.
- Flyway successfully applies the initial migration to PostgreSQL 17.
- The application starts successfully.
- GitHub Actions verifies pull requests using the same Java and PostgreSQL baseline.
